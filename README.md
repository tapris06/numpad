# 넘패드 9키 리듬게임

넘패드의 `1`~`9` 키를 사용하는 Windows용 9키 리듬게임입니다.

## 실행

Windows 배포본은 `build/windows/NumpadNine.exe`를 실행하거나 루트의 `Play.cmd`를 사용합니다. 개발 실행은 `setup.ps1`로 도구를 준비한 뒤 `run.ps1`을 실행합니다. 자세한 조작은 [플레이 안내](docs/play-guide.md)를 참고합니다.

곡 선택 화면에서 **FPS 제한 60·120·180·240**을 선택할 수 있으며 설정을 저장합니다. 기본값은 240입니다. 화면의 설명형 안내 문구는 제거하고 기능명·설정값 위주로 표시합니다.

기본 곡 `첫 회로`는 EASY·NORMAL·HARD를 제공합니다. NORMAL은 4비트의 합성 동타·한 방향 여러 레인 동타·양방향 동타 위주이며, 기존 NORMAL 채보는 HARD로 이동했습니다.

두 번째 샘플 곡 `긴 파동`은 44초·BPM 100의 오리지널 음악으로 EASY·NORMAL·HARD를 제공합니다. EASY는 한 키 유지, NORMAL은 롱노트 겹침·양방향 유지·2색/3색 합성, HARD는 쉬는 박 없는 4비트의 2키 중심 롱잡과 색이 먼저 빠지는 합성 롱노트로 구성했습니다. HARD에서 3키가 필요한 순간은 실제 넘패드의 같은 행·열을 사용합니다. 늘어난 곡 목록은 휠·위아래 버튼·방향키로 탐색합니다.

세 번째 샘플 곡 `스파크 러시`는 44초·BPM 200의 오리지널 음악으로, 동타가 적은 단타 중심 EASY·NORMAL을 제공합니다. EASY는 4비트와 쉼, NORMAL은 4비트 연속 입력과 짧은 8비트 구간으로 구성했고 2키 동타는 각각 2회·4회입니다.

스파크 러시 HARD는 한 마디 고정 트릴에서 합성 동타가 섞인 트릴로 발전하며, 8비트 마디마다 R 또는 C 한 방향을 사용합니다.

상세 내용은 [게임 사양서](docs/game-spec.md)를 기준으로 합니다.

## 기본 구상

- 키 색상 배치: 위에서부터 `빨강·파랑·노랑 / 파랑·노랑·빨강 / 노랑·빨강·파랑`.
- 노트 진행 방향: 위 → 아래, 오른쪽 → 왼쪽. 두 방향이 동시에 등장하며 난이도를 감안하여 채보를 배치합니다.
- 해당 진행 레인의 판정선에 노트가 도달하면 같은 색상의 키를 입력합니다.
- 키를 누르는 순간 판정합니다. 합성 노트는 색상별로 각각 판정하고, 처리한 색상의 이펙트만 출력합니다.
- 합성색 노트로 여러 키의 동시 입력을 표현할 수 있습니다. 예를 들어 3열의 주황색 노트는 `6+9`를 뜻합니다.
- 채보는 키·방향·시간·노트 종류만 기록하며, 색상과 색 합성은 노트를 화면에 표시할 때 처리합니다.
- 기본 모드의 합성색은 빨강+노랑=주황, 빨강+파랑=보라, 파랑+노랑=초록이며, 3색 합성은 검정입니다.
- 색 반전 모드는 RGB 빛 합성을 사용합니다. 빨강+초록=노랑, 초록+파랑=시안, 파랑+빨강=마젠타이며, 3색 합성은 흰색입니다.
- 기본 모드는 흰색 배경·검정 3색 노트, 색 반전 모드는 검정 배경·흰색 3색 노트를 사용합니다. 3색 노트는 해당 레인의 세 키 동시 입력을 뜻합니다.
- 초기부터 롱노트와 롱노트의 색 합성을 지원합니다.
- 롱노트는 시작점 1 + 유지분 2로, 탭노트 3개분의 배점을 갖습니다. 시작점과 유지분은 독립적으로 판정합니다.
- 유지율은 시작점 탭이 굿 이상이면 실제 누른 시점부터 종료까지, 미스이면 채보의 원래 시작점부터 종료까지를 기준으로 계산합니다. 시작점이 미스여도 유지분은 획득할 수 있습니다.
- 유지분 판정은 100% 세부 퍼펙트 / 75% 이상 퍼펙트 / 50% 이상 굿 / 50% 미만 미스이며, 해당 판정 점수에 가중치 2를 적용합니다.
- 판정은 세부 퍼펙트 ±30ms, 퍼펙트 ±60ms, 굿 ±90ms이며, 이른 미스 구간은 -120~-90ms입니다. 같은 키의 처리 가능한 앞선 노트부터 판정합니다.
- 경계값은 더 좋은 판정에 포함합니다. 콤보는 굿 이상으로 집계하며, 미스로 연속 콤보가 끊깁니다.
- 성공과 미스가 동시에 확정되면 기존 콤보를 끊고 성공한 판정 수만큼 새 콤보를 시작합니다.
- 판정별 배분 기준 점수는 세부 퍼펙트 1,010,000 / 퍼펙트 1,000,000 / 굿 500,000이며, 채보 전체 배점 가중치로 나눕니다.
- 점수는 가중치를 반영해 합산한 뒤 현재 표시값과 최종 결과의 소수점을 버립니다.
- 추가 키 자체의 페널티는 없지만, 해당 키의 다음 노트가 판정 범위 안에서 먼저 처리되어 Miss가 날 수 있습니다.
- 방향과 관계없이 같은 키를 동시에 중복 요구하는 배치를 금지합니다. 각 키의 롱노트 닫힌구간 `[시작, 종료]`에는 해당 롱노트 자신의 시작 탭을 제외한 같은 키의 다른 탭을 배치하지 않습니다. 새 롱노트의 시작 탭도 포함합니다.
- 판정선은 우선 3×3 블록에 가깝게 배치합니다.
- 색상 배치·순서·반전 옵션 및 판정선 위치 조절은 후순위입니다.

초기 완료 범위는 음악 플레이부터 결과 화면까지입니다. 채보는 [넘패드 채보 표기](docs/chart-notation.md)로 직접 작성하며, 채보 편집기는 후순위입니다. `R`은 행 방향(오른쪽→왼쪽), `C`는 열 방향(위→아래)이며, `6C/9C`처럼 버튼 번호와 방향을 기록합니다. [작성 예제](examples/charts/spec-demo.npd)와 [키·시간 이벤트 전개 예제](examples/charts/spec-demo.chart.json)를 함께 관리합니다.

판정 시간표와 점수 계산식은 [판정·점수 상세](docs/judgment-and-scoring.md)에 정리합니다.

개발 엔진은 **Godot 4.7.2 .NET + C#**, 렌더러는 **Compatibility**, 배포 대상은 **Windows x86_64**입니다. .NET 10.0.403 SDK와 Godot 에디터를 `.tools`에 준비했습니다. 선택 이유와 입력·음악 시간 처리 기준은 [엔진 결정 문서](docs/engine-decision.md), 구현 범위와 검증 기록은 [구현 현황](docs/implementation-status.md)에 정리했습니다.

[구현 전 최종 점검](docs/preflight-check.md)에 예제 검증 결과, 최종 확정 규칙, 개발 도구와 음원 준비 상태를 기록했습니다.
