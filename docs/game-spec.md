# 넘패드 9키 리듬게임 사양서

- 작성일: 2026-11-03
- 상태: 초기 플레이 버전 구현 / 개선 중
- 목적: 기본 입력 규칙, 노트 표현, 화면 구성을 정리하고 후순위 기능을 구분한다.

이 문서에서 **확정**은 현재 요청으로 정해진 내용, **초안**은 이를 구체화하기 위한 제안, **미정**은 추가 결정이 필요한 내용을 뜻한다. 후순위 기능은 구현 시점이 뒤로 미뤄진 요구사항이다.

## 1. 기본 입력과 색상 배치 — 확정

Windows에서 실행하는 프로그램이며, 넘패드의 `1`~`9` 키를 이용하는 9키 리듬게임이다. 화면의 3×3 블록은 일반적인 넘패드의 물리 배열에 맞춘다. `0`, 소수점, 연산자, Enter 키는 현재 9키 입력 범위에 포함하지 않는다.

개발 엔진은 Godot 4.7.2 .NET, 언어는 C#, 렌더러는 Compatibility다. 초기 배포 대상은 Windows x86_64이며, 개발용 SDK는 .NET 10 x64를 사용한다. 선택 이유와 기술 구성은 [개발 엔진 결정](engine-decision.md)을 따른다.

FPS 제한은 60·120·180·240 중 선택하며 기본값은 240이다. 선택한 값은 저장하고 다음 실행에도 적용한다. 화면은 기능명·설정값 중심으로 구성한다.

곡 선택 화면의 노래 오프셋은 −500~+500ms를 5ms 단위로 조절하며 기본값은 0ms다. 양수는 음악을 늦게, 음수는 일찍 재생한다. 노트의 위치·이동과 판정 시간축은 유지하고 음악 시작 시점만 이동한다. 기존 입력 보정과 독립적인 전역 설정으로 저장하며 다음 플레이부터 적용한다. 일시정지·재개에도 상대 시차를 유지하고, 채보 판정과 오프셋을 적용한 음악 재생이 모두 끝난 뒤 결과로 전환한다.

아래 표는 화면을 보는 방향을 기준으로 한다. 열은 왼쪽부터 1~3열, 행은 위쪽부터 1~3행이다.

| 위치 | 1열 | 2열 | 3열 |
| --- | --- | --- | --- |
| 1행 · 위 | `7` 빨강 | `8` 파랑 | `9` 노랑 |
| 2행 · 가운데 | `4` 파랑 | `5` 노랑 | `6` 빨강 |
| 3행 · 아래 | `1` 노랑 | `2` 빨강 | `3` 파랑 |

색상만 나타내면 다음과 같다.

```text
빨 파 노
파 노 빨
노 빨 파
```

각 행과 열에는 빨강, 파랑, 노랑이 하나씩 있다. 따라서 진행 레인과 색상이 정해지면 입력할 키를 찾을 수 있다.

## 2. 노트 진행 방향 — 확정

두 가지 진행 방향을 지원한다.

| 진행 방향 | 레인 구분 | 입력할 키를 찾는 범위 |
| --- | --- | --- |
| 위 → 아래 | 1~3열 | 해당 열의 세 키 |
| 오른쪽 → 왼쪽 | 1~3행 | 해당 행의 세 키 |

노트는 자신의 레인을 따라 이동한다. 해당 레인의 판정선에 노트가 도달했을 때, 그 레인 안에서 노트와 같은 색상의 키를 입력한다. 화면 전체에서 같은 색인 아무 키나 누르는 방식은 아니다.

두 방향 레인은 시작점부터 판정선까지 같은 길이를 사용하며, 노트의 초당 이동 거리도 같다. 레인 길이는 화면에서 두 방향에 공통으로 확보할 수 있는 공간에 맞춘다. 기본 1440×900 화면 기준 길이는 436이며, 기존 348에서 약 25% 늘렸다.

스크롤 속도는 곡 선택 화면의 `−`·`+` 버튼으로 0.5~5.0배 사이에서 0.1배씩 조절하고 저장한다. 기본값은 1.0배이며 두 방향에 함께 적용한다. 1.0배의 기준 이동 속도는 초당 174 화면 좌표 단위다. 레인이 길어지면 같은 속도로 노트를 더 일찍 볼 수 있도록, 표시 시간 범위를 레인 길이와 속도로 계산한다.

### 기본 배치의 단색 입력표

| 방향 | 레인 | 빨강 | 파랑 | 노랑 |
| --- | --- | --- | --- | --- |
| 위 → 아래 | 1열 | `7` | `4` | `1` |
| 위 → 아래 | 2열 | `2` | `8` | `5` |
| 위 → 아래 | 3열 | `6` | `3` | `9` |
| 오른쪽 → 왼쪽 | 1행 | `7` | `8` | `9` |
| 오른쪽 → 왼쪽 | 2행 | `6` | `4` | `5` |
| 오른쪽 → 왼쪽 | 3행 | `2` | `3` | `1` |

예시:

- 위 → 아래로 진행하는 3열 빨강 노트: `6` 입력.
- 오른쪽 → 왼쪽으로 진행하는 1행 파랑 노트: `8` 입력.

두 방향의 노트는 한 곡에서 동시에 등장한다. 방향별 노트의 비중과 복잡도는 난이도를 감안하여 채보에 배치한다. 서로 다른 방향이 같은 시점에 같은 물리 키를 요구하는 배치는 채보 작성 단계에서 금지한다.

## 3. 3×3 블록과 판정선

### 현재 요구사항 — 확정

- 노트 진행 방향마다 판정선이 있다.
- 초기에는 판정선을 3×3 블록에 가깝게 붙여 배치한다.
- 사용자가 판정선 위치를 조절하는 기능은 후순위다.

### 초기 화면 배치 — 초안

위 → 아래 노트의 판정선은 블록의 위쪽 가장자리, 오른쪽 → 왼쪽 노트의 판정선은 블록의 오른쪽 가장자리 가까이에 둔다.

```text
          1열       2열       3열
           ↓         ↓         ↓
           ↓         ↓         ↓
        ━━━━━━━━━━━━━━━━━━━━━━━━━  위 → 아래 판정선
        [7 빨강]  [8 파랑]  [9 노랑] ┃ ← ← 1행
        [4 파랑]  [5 노랑]  [6 빨강] ┃ ← ← 2행
        [1 노랑]  [2 빨강]  [3 파랑] ┃ ← ← 3행
                                   ┃
                           오른쪽 → 왼쪽 판정선
```

이 도식은 공간 관계를 설명하기 위한 초안이다. 실제 픽셀 간격, 블록 크기, 노트 크기, 화면 비율은 미정이다.

## 4. 합성색을 이용한 동치 노트

### 기본 규칙 — 확정

같은 레인에서 여러 색상의 키를 함께 입력하는 패턴을 하나의 합성색 노트로 표현할 수 있다. 합성색 노트와 그 노트가 나타내는 원색 키 조합은 입력 의미가 같다. 판정은 합성색 전체를 하나로 묶지 않고, 구성하는 각 색상별로 독립적으로 처리한다. 채보에는 키·방향·시간·노트 종류를 기록하며, 색상과 색 합성은 노트 표시 단계에서 처리한다.

기본 모드에서는 빨강·파랑·노랑의 색 합성을 사용하고, 색 반전 모드에서는 빨강·초록·파랑(RGB)의 빛 합성(가산 혼합)을 사용한다. 색 반전 옵션 자체는 후순위다.

### 확정 예시: 3열의 주황색 노트

위 → 아래로 진행하는 3열에는 다음 키가 있다.

| 키 | 색상 |
| --- | --- |
| `9` | 노랑 |
| `6` | 빨강 |
| `3` | 파랑 |

따라서 **3열의 주황색 노트 = 빨강 + 노랑 = `6+9` 동시 입력**이다. `3`은 이 노트의 입력에 포함되지 않는다.

`6`만 유효하게 입력했다면 빨강 성분만 판정하고 빨강 이펙트만 출력한다. 노랑 성분은 그 입력으로 처리하지 않으며, 자신의 입력 여부와 판정 시점에 따라 별도로 처리한다. 합성 노트의 동시 입력은 같은 목표 시점에 여러 색을 요구한다는 뜻이며, 판정은 각 색의 실제 입력 시점을 기준으로 한다.

주황색 노트가 항상 `6+9`를 뜻하는 것은 아니다. 같은 원리를 다른 레인에 적용하면 다음과 같다.

| 방향 | 레인 | 주황색에 대응하는 키 |
| --- | --- | --- |
| 위 → 아래 | 1열 | `7+1` |
| 위 → 아래 | 2열 | `2+5` |
| 위 → 아래 | 3열 | `6+9` |
| 오른쪽 → 왼쪽 | 1행 | `7+9` |
| 오른쪽 → 왼쪽 | 2행 | `6+5` |
| 오른쪽 → 왼쪽 | 3행 | `2+1` |

단타와 롱노트 시작점의 색은 해당 시점에 새로 눌러야 하는 미처리 키만 합성한다. 진행 중인 다른 롱노트의 색은 섞지 않는다. 예를 들어 빨강 롱노트 유지 중 파랑 탭노트가 오면 탭은 파랑으로 표시한다. 롱노트 몸통끼리 겹치는 구간은 기존처럼 합성하므로 빨강·파랑 롱노트의 겹친 몸통은 보라로 표시한다.

### 기본 모드의 합성색 대응 — 확정

기본 모드의 2색 및 3색 합성은 다음과 같다.

| 원색 조합 | 노트 표시색 | 입력 |
| --- | --- | --- |
| 빨강 + 노랑 | 주황 | 해당 레인의 빨강·노랑 키 동시 입력 |
| 빨강 + 파랑 | 보라 | 해당 레인의 빨강·파랑 키 동시 입력 |
| 파랑 + 노랑 | 초록 | 해당 레인의 파랑·노랑 키 동시 입력 |
| 빨강 + 파랑 + 노랑 | 검정 | 해당 레인의 세 키 동시 입력 |

### 색 반전 모드의 RGB 합성 — 확정

색 반전 모드의 기본색은 빨강(R), 초록(G), 파랑(B)이다. 각 노트는 해당 레인에서 표시색을 구성하는 기본색 키를 입력한다.

| 기본색 조합 | 노트 표시색 | 입력 |
| --- | --- | --- |
| 빨강(R) + 초록(G) | 노랑 | 해당 레인의 빨강·초록 키 동시 입력 |
| 초록(G) + 파랑(B) | 시안(청록) | 해당 레인의 초록·파랑 키 동시 입력 |
| 파랑(B) + 빨강(R) | 마젠타(자홍) | 해당 레인의 파랑·빨강 키 동시 입력 |
| 빨강(R) + 초록(G) + 파랑(B) | 흰색 | 해당 레인의 세 키 동시 입력 |

RGB 기본색을 3×3 키 블록의 어느 위치에 배치할지는 미정이다.

### 모드별 배경과 3색 노트 — 확정

| 모드 | 배경색 | 3색 노트 표시색 | 입력 의미 |
| --- | --- | --- | --- |
| 기본 모드 | 흰색 | 검정 | 해당 레인의 세 키 동시 입력 |
| 색 반전 모드 | 검정 | 흰색 | 해당 레인의 세 키 동시 입력 |

3색 노트는 해당 레인의 세 색상을 모두 합성한 노트다. 예를 들어 위 → 아래로 진행하는 3열의 3색 노트는 `3+6+9` 동시 입력을 뜻하며, 기본 모드에서는 검정, 색 반전 모드에서는 흰색으로 표시한다.

합성색의 실제 색상값과 원색을 함께 보여주는 보조 표시 여부는 미정이다. 각 색상의 입력에는 아래 판정 시간 범위와 등급을 독립적으로 적용한다.

## 5. 입력 판정과 롱노트 — 확정

### 입력 시점과 합성 노트

- 키를 누르는 순간을 기준으로 판정한다.
- 키를 미리 누르고 있는 상태만으로 새로운 노트의 시작을 처리하지 않는다.
- 합성 노트의 각 색상은 독립적인 판정 상태를 갖는다.
- 일부 색상만 처리했다면 처리한 색상의 이펙트만 출력한다.

### 추가 키 입력과 다음 노트

불필요한 키를 눌렀다는 이유만으로 별도의 오입력 페널티를 부여하지 않는다. 다만 그 키에도 일반적인 노트 판정이 적용되므로, 판정 범위에 들어온 다음 노트가 먼저 처리되어 Miss가 발생할 수 있다.

예를 들어 `6+9` 주황색 노트에서 `3`까지 눌러도 추가 키 자체를 이유로 주황색 노트를 실패 처리하지 않는다. 대신 `3`에 대응하는 다음 노트가 판정 범위 안에 있다면 그 노트에 영향을 줄 수 있다. 판정 대상 노트가 없는 입력은 별도의 오입력 페널티 없이 처리한다.

같은 키에 대응하는 미처리 노트 중 현재 처리가 가능한 앞선 노트부터 처리한다. 목표 시점이 더 가까운 뒷노트를 우선하지 않는다. 한 번의 키다운은 하나의 색상별 시작 판정을 처리한다.

### 판정 시간 범위

시간 오차는 `입력 시각 - 노트 목표 시각`으로 정의한다. 음수는 이른 입력, 양수는 늦은 입력이다.

| 판정 | 시간 오차 |
| --- | --- |
| 세부 퍼펙트 | ±30ms 이내 |
| 퍼펙트 | ±60ms 이내 중 세부 퍼펙트 구간 제외 |
| 굿 | ±90ms 이내 중 퍼펙트 구간 제외 |
| 미스 | `-120ms ≤ 오차 < -90ms`, `오차 > +90ms` 및 그때까지 미입력 |

- -120ms보다 이른 입력은 해당 노트를 처리하지 않는다.
- 이른 미스 구간의 입력은 해당 노트를 미스로 처리할 수 있으므로, 불필요한 키 입력이 다음 노트에 영향을 줄 수 있다.
- 늦은 미스 구간에 들어간 미처리 노트는 미스로 확정한다.
- 경계값은 더 좋은 판정에 포함한다. 정확히 ±30ms는 세부 퍼펙트, ±60ms는 퍼펙트, ±90ms는 굿이다. 상세 구간은 [판정·점수 상세](judgment-and-scoring.md)를 따른다.

### 롱노트

- 초기 구현부터 롱노트를 포함한다.
- 롱노트에서도 색의 합성이 등장할 수 있다.
- 롱노트의 시작은 키를 누르는 순간을 기준으로 판정한다.
- 합성 롱노트도 각 색상별로 판정 상태와 입력 유지 상태를 구분한다.
- 원색 하나의 롱노트 배점은 시작점 1 + 유지분 2 = 탭노트 3개분이다.
- 시작점은 탭노트와 같은 판정 및 배점을 적용한다.
- 시작점 탭이 굿 이상이면 실제로 누른 시점부터 종료까지의 누적 키다운 비율로 유지율을 계산한다. 해당 누름부터 끝까지 떼지 않았다면 유지율 100%다.
- 시작점 탭이 미스이면 채보의 원래 시작점부터 종료까지의 누적 키다운 비율로 유지율을 계산한다. 늦게 누르기 전의 공백도 비율에 반영한다.
- 유지 중 손을 놓은 시간은 누적 시간에 포함하지 않는다. 유지율은 0~100% 범위다.
- 다시 누른 시간도 누적하며, 판정에 따라 결정된 측정 기준 시각을 재입력으로 초기화하지 않는다.
- 유지분은 100% 세부 퍼펙트, 75% 이상 퍼펙트, 50% 이상 굿, 50% 미만 미스로 판정한다. 높은 등급부터 적용한다.
- 유지율에 따른 판정 등급의 배분 기준 점수에 가중치 2를 적용한다.
- 시작점과 유지분의 등급·점수는 독립적으로 계산한다. 시작점을 미스했어도 원래 시작~종료 구간 안에서 이후 누른 시간을 유지분에 누적한다.
- 끝에서 키를 떼는 순간에 별도의 배점을 부여하지 않는다.
- 색상별 시작·종료가 다른 롱노트도 각 키의 시간 구간과 판정을 따로 관리하여 합성한다.
- 방향과 관계없이 해당 키 롱노트의 채보상 닫힌구간 `[시작, 종료]` 안에는 같은 키의 다른 탭을 배치하지 않는다. 새 롱노트의 시작 탭도 이 규칙에 포함하며, 해당 롱노트 자신의 시작 탭은 제외한다.

누적 시간과 유지율별 판정, 독립 배점 계산식은 [판정·점수 상세](judgment-and-scoring.md)를 따른다.

### 점수와 배점 가중치

| 판정 | 배분 기준 점수 |
| --- | --- |
| 세부 퍼펙트 | 1,010,000 |
| 퍼펙트 | 1,000,000 |
| 굿 | 500,000 |
| 미스 | 0 |

위 점수를 채보 전체의 배점 가중치에 따라 나누어 갖는다. 원색별 단타는 가중치 1, 롱노트는 시작점 1과 유지분 2를 합쳐 가중치 3이다. 합성 노트는 구성 원색별로 합산한다. 예를 들어 2색 단타는 총 가중치 2, 2색 롱노트는 총 가중치 6이다.

전체 배점 가중치는 `단타 원색 이벤트 수 + 3 × 롱노트 원색 이벤트 수`다. 가중치를 반영한 기준 점수 분자를 정수로 합산하고, 이를 전체 가중치로 나눈 표시 점수의 소수점을 버린다.

원색 롱노트 하나의 기여 점수는 `[시작점 판정의 기준 점수 + 2 × 유지분 판정의 기준 점수] / 전체 배점 가중치`다.

### 콤보

세부 퍼펙트·퍼펙트·굿을 성공 콤보로 집계하며, 미스는 연속 콤보를 끊는다. 합성 노트의 원색별 판정과 롱노트의 시작점·유지분 판정에도 각각 이 기준을 적용한다. 판정 대상이 없는 추가 키 입력은 콤보에 영향을 주지 않는다.

같은 순간에 확정되는 판정에 성공과 미스가 섞이면 미스로 기존 콤보를 먼저 끊고, 성공한 판정 수만큼 새 콤보를 시작한다. 예를 들어 현재 콤보가 120이고 동시 성공 2개·미스 1개이면 처리 후 콤보는 2다. 서로 다른 시각의 판정은 발생 순서대로 처리한다.

### 키별 입력 중복 금지

각 물리 키를 독립적으로 검사하며 진행 방향과 관계없이 같은 시점에 같은 키를 중복 요구하는 채보는 허용하지 않는다. 채보에 기록된 개별 버튼 이벤트를 기준으로 검사한다.

예를 들어 위 → 아래 3열의 빨강과 오른쪽 → 왼쪽 2행의 빨강은 둘 다 `6`을 요구하므로 같은 시점에 배치할 수 없다. 서로 다른 키를 요구하는 두 방향의 동시 노트는 배치할 수 있다.

키 k의 롱노트 구간이 `[s, e]`이면 다른 노트의 시작 탭이 같은 키 k를 요구하면서 `s ≤ t ≤ e`를 만족할 경우 채보를 거부한다. 해당 롱노트 자신의 시작 탭은 검사 대상에서 제외한다. 이 규칙은 새 단타와 새 롱노트의 시작 탭에 모두 적용되며, 같은 방향과 반대 방향을 동일하게 처리한다.

예를 들어 `6`의 롱노트가 1000~2000ms이면 `6`을 요구하는 다른 노트의 시작을 1000ms·1500ms·2000ms 어느 시점에도 배치할 수 없다. 다른 키의 노트는 각 키별로 검사한다. 플레이 중 손을 놓았다가 기존 롱노트를 다시 누른 시간은 기존 유지율 규칙에 따라 누적한다.

## 6. 후순위 옵션

| 옵션 | 요구사항 | 추후 정할 사항 |
| --- | --- | --- |
| 노트 위치 미러 | 노트 위치를 바꾸는 옵션 | 반전 축, 적용 방향, 키 블록과의 관계 |
| 색 위치 변경 | 기본 배치 이외의 색상 위치를 지원 | 허용하는 배치와 변경 단위 |
| 색 순서 변경 | 색상의 순서를 바꿀 수 있도록 지원 | 순서의 의미, 색 치환 방식, 적용 범위 |
| 색 반전 | RGB 빛 합성, 검정 배경, 흰색 3색 노트 | RGB 기본색의 키별 배치, 세부 색상값 |
| 판정선 위치 조절 | 기본 위치에서 판정선을 이동 가능 | 이동 축, 조절 범위, 방향별 독립 설정 여부 |

옵션 구상은 노트 위치를 바꾸는 미러에 한정하지 않는다. 색의 위치, 순서, 반전도 별도로 바꿀 수 있어야 한다. 옵션 간 중첩 가능 여부와 적용 순서는 미정이다.

색 반전 모드의 RGB 기본색과 합성색, 검정 배경, 흰색 3색 노트는 확정이다. RGB 기본색의 키별 배치와 실제 표시할 세부 색상값은 추후 정한다.

### 옵션 확장을 위한 설계 방향 — 초안

- 물리 키 위치, 키별 색상 배치, 노트의 진행 방향·레인, 노트가 의미하는 색 조합을 구분해 관리한다.
- 입력할 키는 현재 적용된 배치와 노트의 레인·색 조합으로 결정한다.
- 예시인 `주황 = 6+9`를 모든 레인에 적용되는 고정 규칙으로 구현하지 않는다.
- 옵션 적용 후에도 각 레인에서 색 조합으로 입력 키를 명확히 찾을 수 있어야 한다. 동일 색이 한 레인에 중복되는 배치의 허용 여부는 추후 정한다.

## 7. 채보 작성과 노테이션

### 작성 방식 — 확정

- 채보 노테이션을 먼저 정립한다.
- 초기 채보는 파일을 직접 작성한다.
- 채보 편집기는 후순위다.
- 채보 작성 및 로딩 시 키별 입력 중복을 검증할 수 있어야 한다.
- 각 키 롱노트의 닫힌구간에 동일 키의 다른 시작 탭이 배치됐는지 방향과 관계없이 검증한다.

### 넘패드 채보 표기 v1

채보는 텍스트로 작성한다. 넘패드 버튼 1~9 뒤에 방향 `R`(행, 오른쪽→왼쪽) 또는 `C`(열, 위→아래)를 붙인다. 예를 들어 `6C/9C`는 같은 시점의 두 입력 이벤트이며, 기본 배치에서는 노트 표시 단계에서 3열 주황색으로 합성한다. [채보 표기 사양](chart-notation.md)

BPM `(120)`, 칸 분할 `{4}`, 쉼표, 동시 입력 `/`, 롱노트 `h[분할:개수]`, 종료 `E`를 사용한다. 채보에는 합성색이나 합성 표시 그룹을 기록하지 않는다. 직접 작성하는 [텍스트 예제](../examples/charts/spec-demo.npd)와 [키·시간 이벤트 전개 예제](../examples/charts/spec-demo.chart.json)를 함께 관리한다. C# 파서와 검증 로직을 구현했다.

## 8. 초기 구현 범위

### 완료 범위 — 확정

Windows 프로그램에서 음악을 재생하고, 두 방향의 단타·합성 노트·롱노트를 플레이한 뒤 결과 화면까지 표시한다. 테스트 패턴의 입력 확인에 그치지 않고 한 곡의 플레이 흐름을 완료할 수 있어야 한다.

### 구현 순서 — 초안

기술 스택은 [개발 엔진 결정](engine-decision.md)에 따라 Godot .NET과 C#으로 진행한다. 개발 일정은 아직 정하지 않았다.

1. 노테이션과 채보 검증 규칙 정리, 직접 작성한 채보 로딩.
2. Windows 프로그램의 흰색 배경, 기본 3×3 블록, 넘패드 입력 연결.
3. 음악 재생 시점을 기준으로 두 방향의 노트 이동과 판정 동기화.
4. 단타 및 2색·3색 합성 노트의 색상별 판정과 이펙트.
5. 롱노트 및 합성 롱노트의 시작·유지·종료 처리.
6. 난이도를 감안한 채보를 한 곡 끝까지 플레이하고 결과 표시.

초기 검증 항목:

- 화면의 키 번호와 실제 넘패드 위치가 일치하는가.
- 두 방향의 노트가 동시에 등장하며 음악과 동기화되는가.
- 같은 색이라도 해당 진행 레인에 속하는 키만 올바른 입력으로 인식하는가.
- 미리 누른 상태만으로 새로운 노트가 처리되지 않는가.
- 3열 주황색 노트는 `6+9`를 요구하는가.
- 주황색 노트에 `6`만 유효하게 입력하면 빨강 성분만 판정하고 빨강 이펙트만 출력하는가.
- 기본 모드에서 보라 노트는 빨강·파랑, 초록 노트는 파랑·노랑 키 조합을 요구하는가.
- 기본 모드의 배경은 흰색이며, 검정 3색 노트는 해당 레인의 세 키를 모두 요구하는가.
- 추가 키 입력 자체로 페널티를 주지 않으면서 해당 키의 다음 노트에는 판정 규칙을 적용하는가.
- 같은 키에 처리 가능한 노트가 여러 개라면 앞선 노트가 먼저 처리되는가.
- 세부 퍼펙트·퍼펙트·굿·미스의 판정 시간 범위가 적용되는가.
- 정확한 ±30/60/90ms와 유지율 100%·75%·50% 경계에 더 좋은 판정이 적용되는가.
- 단색·합성 롱노트를 플레이할 수 있는가.
- 롱노트가 시작점 가중치 1과 유지율별 판정에 따른 유지분 가중치 2로 계산되는가.
- 롱노트 유지율 100%·75%·50%에서 각각 세부 퍼펙트·퍼펙트·굿이 적용되는가.
- 시작점을 미스한 롱노트도 이후 누른 시간에 따라 유지분 점수를 획득하는가.
- 시작점이 굿 이상이면 실제 키다운, 미스이면 원래 시작점을 유지율 측정의 기준으로 삼는가.
- 동일 키 입력 중복을 진행 방향과 관계없이 채보 검증에서 검출하는가.
- 동일 키 롱노트의 시작점·유지 구간·종료점에 다른 노트의 시작 탭이 있으면 거부하는가.
- 두 진행 방향의 판정선이 블록 가까이에 표시되는가.
- 음악 플레이를 완료하면 결과 화면이 표시되는가.
- 굿 이상으로 콤보가 집계되고 미스로 연속 콤보가 끊기는가.
- 동시 성공·미스가 섞이면 기존 콤보를 끊고 성공 수만큼 새 콤보를 시작하는가.
- 점수의 가중치 분자를 합산해 나눈 뒤 소수점이 버려지는가.

후순위인 색 반전 모드를 구현할 때는 RGB 합성표에 맞는 입력, 검정 배경, 흰색 3색 노트, 해당 레인의 세 키 동시 입력을 확인한다.
