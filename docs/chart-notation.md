# 넘패드 채보 표기 v1

- 작성일: 2026-11-03
- 상태: 프로젝트용 작성 사양 / C# 파서 구현
- 기준: [게임 사양서](game-spec.md), [판정·점수](judgment-and-scoring.md)
- 작성 예제: [spec-demo.npd](../examples/charts/spec-demo.npd)
- 이벤트 전개 예제: [spec-demo.chart.json](../examples/charts/spec-demo.chart.json)

이 표기를 설계할 때 simai를 참고했다.

**채보에는 버튼, 진행 방향, 목표 시각, 노트 종류와 길이를 기록한다. 색상과 색 합성은 노트 표시 단계에서 계산한다.** 합성색이나 합성 표시 그룹을 지정하는 필드는 사용하지 않는다.

## 1. 버튼과 진행 방향

버튼 번호는 실제 넘패드 키 번호다.

```text
7 8 9
4 5 6
1 2 3
```

| 접미사 | 의미 | 화면 진행 | 레인 결정 |
| --- | --- | --- | --- |
| `R` | Row · 행 방향 | 오른쪽 → 왼쪽 | 해당 버튼이 속한 행 |
| `C` | Column · 열 방향 | 위 → 아래 | 해당 버튼이 속한 열 |

`6C`는 위에서 내려오는 `6` 키 노트, `6R`은 오른쪽에서 오는 `6` 키 노트다. 행은 화면 위부터 1~3행, 열은 왼쪽부터 1~3열이다.

| 버튼 | `R`의 레인 | `C`의 레인 | 기본 배치에서 표시할 원색 |
| --- | --- | --- | --- |
| `1` | 3행 | 1열 | 노랑 |
| `2` | 3행 | 2열 | 빨강 |
| `3` | 3행 | 3열 | 파랑 |
| `4` | 2행 | 1열 | 파랑 |
| `5` | 2행 | 2열 | 노랑 |
| `6` | 2행 | 3열 | 빨강 |
| `7` | 1행 | 1열 | 빨강 |
| `8` | 1행 | 2열 | 파랑 |
| `9` | 1행 | 3열 | 노랑 |

이 표의 원색은 렌더러가 기본 배치를 적용한 결과다. 채보 본문에는 색상 이름을 쓰지 않는다. 후순위인 미러·색상 옵션의 변환 순서는 옵션 구현 시 정의한다.

## 2. 기본 문법 요약

| 표기 | 의미 |
| --- | --- |
| `(120)` | 이후 BPM을 120으로 설정 |
| `{4}` | 쉼표 한 칸을 4분음표 길이로 설정 |
| `{8}` | 쉼표 한 칸을 8분음표 길이로 설정 |
| `,` | 현재 칸을 끝내고 한 칸 진행. 빈 칸이면 쉼 |
| `6C` | 현재 시점에 `6` 키의 열 방향 단타 |
| `6R/9C` | 현재 시점에 두 노트를 동시에 배치 |
| `69C` | `6C/9C`와 같은 단타 축약 |
| `6Ch[4:2]` | `6` 키의 열 방향 롱노트, 4분음표 2개 길이 |
| `6Rh[#1.5]` | `6` 키의 행 방향 롱노트, 1.5초 길이 |
| `E` | 현재 시점을 채보 종료 시점으로 기록 |

방향 접미사는 바로 앞 숫자열 전체에 적용한다. 각 숫자는 독립된 입력 이벤트로 전개한다.

## 3. 파일 구성

UTF-8 텍스트 파일을 사용하며 확장자는 `.npd`로 한다. 초기 버전은 파일 하나에 채보 하나를 기록한다.

| 항목 | 필수 여부 | 의미 |
| --- | --- | --- |
| `format` | 필수 | `numpad-chart-v1` |
| `title` | 필수 | 곡 이름 |
| `artist` | 선택 | 아티스트 |
| `difficulty` | 선택 | 난이도 이름 |
| `audio` | 필수 | 채보 파일 기준 음원 상대 경로 |
| `first` | 필수 | 음원 시작에서 채보 첫 칸까지의 오프셋, 초 단위 |
| `inote` | 필수 | 다음 줄부터 채보 본문 |

메타데이터는 한 줄에 한 항목을 쓰고 첫 `=` 뒤를 그 줄의 값으로 읽는다. 같은 필드를 중복하거나 본문 뒤에 새 메타데이터를 기록하지 않는다. 곡명 등은 UTF-8 문자열 그대로 기록한다.

`first=1.234`이면 첫 칸은 음원 기준 1.234초다. 기존 밀리초 오프셋과의 관계는 `offset_ms = first × 1000`이다. 본문에서 공백·탭·줄바꿈은 시간을 진행시키지 않는다. 본문 한 줄의 `//` 이후는 작성용 주석으로 처리한다.

## 4. BPM, 분할, 쉼

첫 칸 전에 BPM과 분할을 모두 선언한다. 함께 선언할 때 순서는 `(BPM){분할}`이다. BPM은 양수 소수, 분할은 양의 정수로 쓴다. 각 칸은 현재 시점의 이벤트를 기록한 다음 쉼표로 전진한다.

```text
쉼표 한 칸의 길이(초) = 240 / BPM / 분할
```

`(120){4}`는 한 칸 0.5초, `(120){8}`은 0.25초다. `{12}`는 4분음표 한 박을 세 칸으로 나누는 길이다.

```text
(120){4}
6C,,9R,
E
```

`first=0`일 때 위 예제의 `6C`는 0초, 두 번째 칸은 쉼, `9R`은 1초에 도달한다. `E`는 1.5초다.

BPM과 분할은 칸의 노트 앞에서 변경한다.

```text
(120){4}6C,
(180){8}9R,
E
```

`{#0.35}`는 이후 한 칸을 0.35초로 지정한다. 이 설정은 다음 분할 지정까지 유지하며 BPM 변경만으로 바뀌지 않는다. `{8}`처럼 다시 지정하면 BPM 기반 길이로 전환한다. 초 단위 칸에서도 음표 길이로 롱노트를 지정하려면 BPM이 선언되어 있어야 한다.

## 5. 단타와 동시 입력

```text
1R,2C,3R,4C,5R,6C,7R,8C,9R,
```

각 항목은 자기 칸에서 해당 버튼 하나를 입력한다. 버튼 뒤의 `R`·`C`는 대문자다. 방향을 생략하거나 앞 노트의 방향을 상속하지 않는다.

동시 입력은 `/`로 구분한다. `/`는 시간을 진행시키지 않으며, 서로 다른 방향·레인도 함께 기록할 수 있다.

```text
6C/9C,
6C/9C/3R,
```

같은 방향의 단타는 숫자를 이어 축약할 수 있다.

```text
69C,       // 6C/9C
69C/3R,    // 6C/9C/3R
258C/7R,  // 2C/5C/8C/7R
```

축약은 입력 이벤트를 줄여 쓰는 규칙이다. `12C`는 서로 다른 열의 두 노트다. 같은 칸에 같은 버튼을 중복 기록하지 않는다. 롱노트는 각 버튼을 따로 기록한다.

## 6. 롱노트

기본형은 `버튼 + 방향 + h + [길이]`다. 길이는 반드시 명시한다.

| 표기 | 길이 |
| --- | --- |
| `7Ch[4:4]` | 현재 BPM의 4분음표 4개 |
| `4Rh[8:3]` | 현재 BPM의 8분음표 3개 |
| `6Ch[#1.5]` | 1.5초 |
| `9Rh[180#4:3]` | BPM 180 기준 4분음표 3개, 1초 |

```text
[d:n]의 길이(초) = 240 / 시작 시점의 BPM / d × n
[b#d:n]의 길이(초) = 240 / b / d × n
[#s]의 길이(초) = s
```

`d`와 `n`은 양의 정수, `b`와 `s`는 양수다. 길이는 노트 시작 시 계산한 초 단위 값으로 고정한다. 이후 BPM이나 칸 길이가 바뀌어도 이미 시작한 롱노트의 종료 시각은 유지한다. `[b#d:n]`의 BPM은 해당 길이 계산에만 사용한다.

```text
7Ch[4:4]/4Ch[4:2],
```

여러 버튼의 롱노트는 위처럼 `/`로 나열한다. 채보에는 각 버튼의 시작과 길이만 있다. 서로 다른 칸에 시작하거나 서로 다른 시점에 끝나는 롱노트도 각각 기록한다.

## 7. 색 합성은 노트 표시에서 처리

1. 채보를 버튼·방향·시작 시각·종료 시각의 개별 이벤트로 전개한다.
2. 표시 단계에서 현재 배치에 따라 각 버튼의 레인과 원색을 구한다.
3. 같은 방향·같은 레인의 같은 시점 단타 또는 겹치는 롱노트 구간을 색 합성으로 표시한다.
4. 판정, 점수, 콤보, 처리 이펙트는 개별 이벤트를 기준으로 관리한다.

기본 모드의 표시 예시:

| 채보의 입력 이벤트 | 노트 표시 결과 |
| --- | --- |
| 같은 시점의 `6C/9C` | 3열의 빨강·노랑을 주황색으로 합성 |
| 같은 시점의 `2C/8C/5C` | 2열의 세 원색을 검정으로 합성 |
| `7C` 롱노트와 `4C` 롱노트의 겹치는 구간 | 1열의 빨강·파랑을 보라색으로 합성 |
| 같은 시점의 `6C/9C/3R` | 3열 주황색과 3행 파랑을 각 방향에 표시 |

한 색만 유효하게 처리했다면 해당 색의 판정과 이펙트만 출력한다. 기본 모드·RGB 반전 모드의 합성표와 배경은 게임 사양을 따른다. 합성 결과를 채보에 저장하지 않는다.

## 8. 전체 예제

[예제 파일](../examples/charts/spec-demo.npd)은 다음과 같다. 음원 경로는 실제 곡을 준비할 때 교체할 값이다.

```text
&format=numpad-chart-v1
&title=사양 확인용 예제
&difficulty=test
&audio=music.wav
&first=0
&inote=
(120){4}
6C/9C/3R,
,
7Ch[4:4],
4Ch[4:2],
,
,
,
,
2C/8C/5C/7R,
E
```

| 위치 | 음원 시각 | 기록한 이벤트 | 기본 모드 표시 |
| --- | --- | --- | --- |
| 0박 | 0초 | `6C/9C/3R` | 3열 주황 단타 + 3행 파랑 단타 |
| 2박 | 1초 | `7Ch[4:4]` 시작 | 1열 빨강 롱노트 시작 |
| 3박 | 1.5초 | `4Ch[4:2]` 시작 | 겹치는 3~5박 구간은 보라 |
| 5박 | 2.5초 | `4C` 롱노트 종료 | 남은 5~6박 구간은 빨강 |
| 6박 | 3초 | `7C` 롱노트 종료 | 1열 롱노트 종료 |
| 8박 | 4초 | `2C/8C/5C/7R` | 2열 검정 단타 + 1행 빨강 단타 |
| 9박 | 4.5초 | `E` | 채보 종료 |

단타 입력 7개, 롱노트 입력 2개이므로 총 배점 가중치는 `7 + 3 × 2 = 13`이다. 롱노트 길이가 달라도 개별 최대 가중치는 3이다.

이벤트 전개 JSON의 `time_ms`와 노트별 `end_ms`는 `first`를 이미 반영한 음원 기준 밀리초 시각이다. 최상위 `end_ms`는 `E`의 시각이다. 전개 결과에 오프셋을 다시 더하지 않는다.

`E`는 채보 종료 시각이다. 모든 롱노트와 마지막 노트의 판정 가능 시간이 종료되도록 배치한다. 음악은 곡 끝까지 재생하며, 결과 화면은 음악 재생과 판정이 모두 완료된 뒤 표시한다.

## 9. 문법 정의

메타데이터 이후 본문에 대한 EBNF 요약이다. `number`는 소수부를 선택적으로 가진 양의 십진수, `integer`는 양의 정수다. 본문의 주석을 제거한 뒤 공백을 정리한다.

```text
body       = { cell, "," }, "E" ;
cell       = { directive }, [ notes ] ;
notes      = note, { "/", note } ;
note       = tap | hold ;
tap        = button, { button }, axis ;
hold       = button, axis, "h", "[", length, "]" ;
axis       = "R" | "C" ;
button     = "1" | "2" | "3" | "4" | "5" | "6" | "7" | "8" | "9" ;
directive  = "(", number, ")"
           | "{", integer, "}"
           | "{#", number, "}" ;
length     = integer, ":", integer
           | "#", number
           | number, "#", integer, ":", integer ;
```

BPM·분할의 사전 선언, 양수 검사, 시간·키 충돌은 의미 검증으로 처리한다. 본문 시작의 설정은 첫 칸에 적용한다. `E` 뒤에는 공백과 주석만 허용한다.

## 10. 채보 검증과 적용 범위

- 버튼 1~9, 방향 `R`·`C`, 단타·롱노트 형식을 검사한다.
- 같은 시점에 같은 물리 키를 중복 요구하는 이벤트를 거부한다. `6R/6C`도 중복이다.
- 키별로 롱노트의 채보상 닫힌구간 `[시작, 종료]` 안에 같은 키의 다른 시작 탭이 있으면 방향과 관계없이 거부한다.
- 해당 롱노트 자신의 시작 탭은 제외하며, 다른 단타와 새 롱노트의 시작 탭을 모두 검사한다. 같은 키 롱노트끼리 구간이 겹치거나 끝과 시작이 맞닿는 배치도 금지한다.
- 롱노트 길이는 0보다 커야 하며 `E`는 모든 노트의 종료·판정 완료 시점 이후에 둔다.
- 알 수 없는 기호나 지원하지 않는 노트 종류는 오류 위치와 함께 보고한다.
- 합성 표시 결과는 채보 입력 검증과 점수 가중치를 바꾸지 않는다.

`(120){4}6Ch[4:1],6C,E`는 첫 롱노트가 끝날 때 같은 키를 다시 입력하므로 거부한다. `(120){4}6Ch[4:2],6C,,E`는 같은 방향이지만 유지 구간 안의 동일 키 탭이므로 거부한다. `6,`은 방향 누락, `0C,`는 버튼 범위 오류, `6Ch,`는 길이 누락, `69Ch[4:1],`은 롱노트 축약 오류다.

초기 범위는 단타·롱노트, BPM·분할·초 단위 간격, 동시 입력이다. [JSON 예제](../examples/charts/spec-demo.chart.json)는 키·시간 이벤트 전개 결과의 참고 자료이며, 직접 작성하는 기준은 이 문서의 텍스트 표기다. 게임용 파서와 키별 충돌 검증을 구현했으며 채보 편집기는 후순위다.
