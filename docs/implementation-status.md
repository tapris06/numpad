# 구현 현황

- 갱신일: 2026-11-04
- 단계: Windows 초기 플레이 버전
- 실행 파일: [NumpadNine.exe](../build/windows/NumpadNine.exe)
- 배포 파일: [Windows x64 ZIP](../build/NumpadNine-Windows-x64.zip)

## 구현 범위

- Godot 4.7.2 .NET + C#, Compatibility 렌더러.
- 곡 선택, 기본 곡 세 개·채보 아홉 개, 외부 `.npd` 열기.
- 기존 NORMAL 패턴을 HARD로 보존. 새 NORMAL은 BPM 120·4비트의 2~3키 동타 위주이며 합성·한 방향 여러 레인·양방향 동타를 배치.
- 새 NORMAL은 102개 단타, 동타 시점 48회(세 유형 각각 16회), 종료 시각 35.5초. 채보 표기·동시 키 중복·4비트 배치를 정적으로 확인.
- 기본 채보와 외부 채보를 함께 보관. 휠·목록 버튼·방향키로 목록을 이동하고 선택 항목을 화면에 표시.
- 36초짜리 프로젝트 자체 생성 음악 `첫 회로`.
- 44초·BPM 100의 프로젝트 자체 생성 음악 `긴 파동`과 EASY·NORMAL·HARD. 생성 소스는 `tools/generate_long_wave.py`.
- `긴 파동` EASY: 롱노트 16개·탭 8개, 동시 유지 최대 1키. NORMAL: 롱노트 40개·탭 8개, 동시 유지 최대 3키.
- 두 채보는 4비트 간격으로 구성하며 42.8초에 종료. 생성 시 같은 키의 동시 입력·롱노트 닫힌구간 중복과 음원 길이를 정적으로 확인.
- `긴 파동` HARD: 롱노트 40개·탭 52개, 본 구간 64박 모두 새 입력, 8비트 분할 없음. 유지 키를 합쳐 2키를 요구하는 박 48회, 새 3키 동타 4회, 합성 롱노트의 색이 먼저 빠지는 구간 16회.
- HARD의 모든 시점에서 유지 키·종료 키·새 입력을 합쳐 최대 3키. 3키이면 물리 넘패드의 같은 행 또는 열이어야 하며 표시 방향은 자유. 생성 시 모든 시작·종료 경계와 경계 사이 구간을 정적으로 확인.
- 새 3키 동타는 4·8·12·16마디 끝에 배치하며 앞선 롱노트는 한 박 먼저 종료. `456C`, `14C/7R`, `789R`, `78R/9C`로 서로 다른 읽기 형태를 사용.
- 44초·BPM 200의 프로젝트 자체 생성 음악 `스파크 러시`와 동타가 적은 단타 중심 EASY·NORMAL. 생성 소스는 `tools/generate_spark_rush.py`.
- `스파크 러시` EASY: 83노트·입력 시점 81회·2키 동타 2회(2.47%), 4비트와 쉼. NORMAL: 132노트·입력 시점 128회·2키 동타 4회(3.12%), 4비트 연속 입력과 네 구간의 8비트 3연타.
- 두 새 채보 모두 롱노트·3키 동타 없이 41.6초에 종료. 생성 시 박 길이·같은 시각의 물리 키 중복·최대 2키·동타 비중 5% 이하·음원 길이를 정적으로 확인.
- `스파크 러시` HARD는 315노트, 8비트 28마디와 4비트 전환 4마디로 구성. 한 마디 고정 단타 트릴에서 합성 동타 교대와 기준 키 전환으로 발전하며, 생성 시 8비트 마디별 방향이 하나인지 확인한다.
- 넘패드 1~9 입력, R/C 두 방향, 단타와 롱노트.
- 노트 표시 단계의 RYB 색 합성과 겹치는 롱노트 구간 표시. 색 반전을 켜면 1·5·9번을 초록으로 표시하고, 검정 배경과 RGB 합성색을 적용한다. 설정은 다음 실행에도 적용된다.
- 단타·롱노트 시작점은 새로 입력할 키만 색 합성. 진행 중인 롱노트의 색과 분리하고 롱노트 몸통 겹침은 유지.
- 원색별 판정·이펙트, 시작점과 유지분의 개별 판정.
- 확정된 판정 경계, 롱노트 닫힌구간 검사, 앞선 노트 우선 처리.
- 가중치 점수와 소수점 버림, 동시 성공·MISS 콤보 처리.
- 일시정지·재개, 재시작, 결과 화면.
- 스크롤 속도 0.5~5.0배를 0.1배 단위로 조절·저장, 기본값 1.0배.
- 입력 보정, 음악 볼륨, 설정 저장.
- 노래 오프셋 −500~+500ms를 5ms 단위로 조절·저장, 기본값 0ms. 음악 시작을 독립적으로 이동하고 노트 표시·판정 시간축 유지.
- 두 방향 레인 길이와 초당 노트 이동 거리 통일, 공통 스크롤 속도 적용.
- 레인 길이를 기본 화면 기준 348에서 436으로 약 25% 확장. 속도에 따른 표시 시간·시작 대기 시간 반영.
- FPS 제한 60·120·180·240 선택·저장, 기본값 240.
- 화면의 설명형 안내 문구 삭제.

## 검증 기록

FPS 설정 및 안내 문구 변경 요청 전에 수행한 검증:

- 핵심 로직 35개 항목, 182개 확인 통과.
- 기본 예제와 문서의 전개 결과 일치.
- EASY·당시 NORMAL(현재 HARD) 채보의 핵심 로직 자동 연주에서 최대 점수 도달.
- 실제 Godot 당시 NORMAL(현재 HARD) 자동 연주: 1,010,000점, 최대 콤보 125, MISS 0, 결과 화면 전환.
- 곡 선택, 재시작, 일시정지와 곡 선택 복귀 확인.
- Windows 입력 이벤트에서 넘패드 1~9의 키다운·키업 매핑 확인.

이후 FPS 선택·저장, 문구 삭제, 두 방향 레인 길이·속도 통일, 수치형 속도 조절과 레인 확장, 노래 오프셋, 탭 표시색과 롱노트 몸통 합성의 분리, NORMAL 신설과 기존 채보의 HARD 이동을 반영했으며, 요청에 따라 추가 플레이 테스트는 진행하지 않았다. 해당 변경을 포함한 Windows Release 빌드·내보내기를 완료하고 게임 DLL, 핵심 로직 DLL과 .NET 런타임의 배포 포함 여부를 확인했다.

2026-11-04에는 `긴 파동` 음원·EASY/NORMAL과 곡 목록 스크롤을 추가하고, 4비트 롱잡 중심 HARD를 추가했다. 음원 생성·채보 정적 확인과 Windows 빌드·내보내기를 수행하며 플레이 테스트는 사용자에게 맡긴다.

같은 날 고속 단타 샘플 `스파크 러시`와 EASY/NORMAL을 추가했다. 음원 생성과 채보 정적 확인 후 Windows 빌드·내보내기에 반영하며 플레이 테스트는 진행하지 않는다.

## 후순위

미러·색 위치·순서 변경, 판정선 위치 조절, 채보 편집기는 기존 사양대로 후순위다. 실제 입력 지연·음원 지연·동시 입력 하드웨어에 따른 체감은 사용자 테스트 결과를 반영해 조정한다.
